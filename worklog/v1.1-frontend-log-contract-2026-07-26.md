## 2. 最终契约

1. 单 Pod 下拉调用
   `GET /discovery/namespaces/{namespace}/pods?label_selector=...`，不再通过 namespace
   inspection 获取 Pod 列表。
2. 日志页 namespace POST 明确发送 `include_logs: true`。
3. 状态页复用的 namespace hook 默认发送 `include_logs: false`。
4. cluster 状态巡检调用
   `POST /inspections/cluster/run?include_logs=false`。
5. 前端从 Settings 的 `inspection_policy.max_log_pods` 读取当前上限；设置页支持
   1 至 1000 的整数配置，并说明只影响范围日志采集、单 Pod 不受影响。
6. 已知范围超过当前上限、Pod 数量未知或上限读取失败时均不发送 namespace
   inspection POST，不提供绕过按钮。

## 4. 验收覆盖

- 单 Pod 下拉只触发轻量 discovery，未触发 namespace inspection。
- 切换 namespace 时立即清空旧 Pod，并只展示新 namespace 的 discovery 结果。
- 全部 Pod 与 Label Selector 日志巡检 body 均明确包含 `include_logs:true`。
- 状态页 namespace 证据读取 body 明确包含 `include_logs:false`。
- cluster 状态巡检 URL 明确包含 `include_logs=false`。
- 以 Settings 返回的 120 为测试上限，121 个 Pod 被前端硬阻断，证明未硬编码 200。
- Pod 数量未知时硬阻断；两种阻断都没有“仍要继续”，也没有发送 POST。
- Settings 对 `max_log_pods` 做 1 至 1000 整数校验，保存值进入完整 policy。
- 单 Pod 巡检不经过范围上限门禁。
