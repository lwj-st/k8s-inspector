# K8s Inspector v1.3.0 产品需求文档

## 1. 文档信息

- 产品：K8s Inspector
- 版本：v1.3.0
- 文档状态：草案
- 制定日期：2026-08-06
- 前置版本：v1.2.0

## 1.1 需求优先级规则

开发和验收过程中，如果本文档与用户后续口述需求冲突，以用户最新口述需求为准，并同步更新本文档。

## 2. 版本判断

本次功能建议命名为 v1.3.0，不建议直接命名为 v2.0.0。

原因：

1. 本次仍然保持单集群、只读、单管理员、SQLite 单副本这些 v1.x 产品边界。
2. 本次是在已有日志巡检能力上增强“按复现窗口保存日志”，属于重要功能增强，但不是架构断代。
3. 不引入外部日志平台，不做多集群，不做复杂权限体系，不做自动修复。
4. 如果后续要接入 Loki/ELK、支持多集群、多用户权限、日志检索引擎或长期大规模日志平台化，再升级 v2.0.0 更合理。

## 3. 背景

生产环境排障时，用户经常遇到这样的问题：

1. 系统页面或接口出错，但不知道具体是哪一个 Pod 出问题。
2. 直接查历史日志时，日志量很大，时间范围不准，难以定位。
3. 用户更希望点击“开始记录”后去业务系统复现问题，等复现完成后点击“结束记录”。
4. 系统只保存这段复现时间窗口里的日志，后续可以按名称空间、Pod 查看和搜索。

v1.3.0 需要提供“复现日志记录”能力：用户在 K8s Inspector 中选择名称空间并开始记录，然后离开 K8s Inspector 去其他业务页面复现问题。系统在后台记录该名称空间下所有 Pod 的窗口日志，结束后长期保存，并支持查看、搜索、命名、改名、删除和模板匹配。

## 4. 产品目标

1. 用户可以选择一个名称空间，点击开始后记录该名称空间下所有 Pod 的新增日志。
2. 用户可以去其他业务系统页面复现问题，不需要在 K8s Inspector 内嵌业务页面。
3. 系统只记录开始时间到结束时间之间的日志。
4. 系统默认 20 分钟自动结束，避免用户忘记关闭。
5. 每次记录都保存为一条可命名的日志记录。
6. 日志记录长期保存，支持后续查看、搜索、改名和删除。
7. 打开日志记录后，先选择名称空间，再进一步选择对应 Pod 查看日志。
8. 日志中支持关键字搜索和高亮。
9. 支持重复日志过滤，避免某个 Pod 一直打印相同日志导致结果不可读。
10. 支持对某次日志记录执行模板匹配，且只匹配包含日志条件的模板。

## 5. 非目标

v1.3.0 不做以下事项：

1. 不内嵌业务系统页面。
2. 不做完整日志平台，不替代 Loki、ELK、OpenSearch。
3. 不跨名称空间一次性记录全集群日志。
4. 不自动判断唯一故障 Pod，只提供更准确的日志窗口和辅助匹配。
5. 不做自动修复。
6. 不执行 Pod exec。
7. 不修改业务 Deployment，不注入 sidecar。
8. 不新增多用户、多租户权限体系。

## 6. 核心流程

### 6.1 开始记录

1. 用户进入“复现日志”页面。
2. 用户选择名称空间。
3. 用户填写日志名称。
4. 用户选择记录时长，默认使用系统默认时长。
5. 用户可选填写备注。
6. 系统预估该名称空间下 Pod 数和容器数。
7. 用户点击“开始记录”。
8. 系统记录触发时间、计划自动结束时间，并开始采集该名称空间下所有 Pod 的新增日志。
9. 用户离开 K8s Inspector，去业务系统页面复现问题。

### 6.2 结束记录

1. 用户复现完成后回到 K8s Inspector。
2. 用户点击“结束记录”。
3. 系统记录结束时间。
4. 系统停止采集。
5. 系统生成日志记录详情。

### 6.3 自动结束

1. 如果用户忘记点击结束，系统默认 20 分钟后自动结束。
2. 自动结束时间必须可在系统配置中修改。
3. 自动结束后，日志记录状态显示为“已自动结束”。
4. 自动结束的日志仍然可以正常查看、搜索、改名、删除和模板匹配。

## 7. 功能需求

### FR-01 复现日志入口

系统必须新增“复现日志”入口，用于按名称空间记录复现期间日志。

#### 需求

1. 左侧导航新增“复现日志”。
2. 页面包含：
   - 开始记录表单
   - 当前运行中的记录
   - 历史日志记录列表
3. 开始记录表单包含：
   - 日志名称
   - 名称空间
   - 记录时长
   - 备注
4. 日志名称必填。
5. 名称空间必选。
6. 页面不提供业务页面内嵌能力。
7. 页面提示用户：开始后可去业务系统复现问题，完成后回到本页面结束记录。

#### 验收标准

1. 用户可以选择名称空间并开始记录。
2. 未填写日志名称时不能开始。
3. 未选择名称空间时不能开始。
4. 页面没有内嵌业务 URL 或 iframe。

### FR-02 日志记录元信息

每次日志记录必须保存排障所需的关键信息。

#### 需求

1. 每次记录至少保存：
   - 日志记录 ID
   - 日志名称
   - 名称空间
   - 触发时间
   - 计划自动结束时间
   - 结束时间
   - 本次记录时长
   - 记录时长来源
   - 记录状态
   - 结束原因
   - 涉及 Pod 数
   - 涉及容器数
   - 日志总行数
   - 日志总字节数
   - 去重后日志行数
   - 备注
   - 创建人
2. 记录状态包括：
   - 记录中
   - 已结束
   - 已自动结束
   - 失败
3. 结束原因包括：
   - 用户手动结束
   - 到达系统默认时长自动结束
   - 到达本次指定时长自动结束
   - 采集失败
   - 系统重启后恢复失败
4. 日志名称支持后续修改。
5. 备注支持后续修改。

#### 验收标准

1. 记录详情能看到触发时间和结束时间。
2. 自动结束的记录能看到结束原因。
3. 修改日志名称后，列表和详情都展示新名称。

### FR-03 按名称空间记录所有 Pod 日志

系统必须按用户选择的名称空间记录所有 Pod 的新增日志。

#### 需求

1. 开始记录后，系统采集该名称空间下所有当前 Pod 的日志。
2. 采集范围包括每个 Pod 下的所有容器。
3. 记录开始后新创建的 Pod 也应纳入采集。
4. 记录期间删除的 Pod，应保留已采集日志，并标记 Pod 已删除。
5. 系统只记录开始后的新增日志，不主动保存开始前历史日志。
6. 如果 Kubernetes 日志接口不支持精确开始时间，则必须用采集启动时间作为近似边界，并在记录详情中说明。
7. 采集失败的 Pod 必须记录失败原因。

#### 验收标准

1. 选择 `demo` 名称空间后，该名称空间下多个 Pod 的日志都能被记录。
2. 开始前的日志不会默认出现在记录中。
3. 记录期间新建 Pod 的日志能被采集。
4. 删除 Pod 后，历史采集内容仍可查看。

### FR-04 记录时长与自动关闭

系统必须防止用户忘记结束记录。

#### 需求

1. 默认记录时长为 20 分钟。
2. 默认记录时长可在系统配置中修改。
3. 开始记录表单提供记录时长下拉选择。
4. 下拉选项固定包含：
   - 使用系统默认
   - 5 分钟
   - 10 分钟
   - 15 分钟
   - 20 分钟
   - 自定义
5. 默认选中“使用系统默认”。
6. “使用系统默认”必须展示当前系统默认值，例如“使用系统默认（20 分钟）”。
7. 选择“自定义”后显示分钟输入框。
8. 自定义时间只允许输入整数分钟。
9. 自定义时间范围：
   - 最小 1 分钟
   - 最大 120 分钟
10. 最大允许记录时长可在系统配置中修改，默认 120 分钟。
11. 如果系统最大允许记录时长小于某个快捷选项，该快捷选项必须禁用或隐藏。
12. 点击开始记录后，后端必须计算并保存计划自动结束时间。
13. 计划自动结束时间等于触发时间加上本次选择的记录时长。
14. 即使用户选择了固定时长或自定义时长，也可以随时手动结束记录。
15. 运行中的记录第一版不支持修改记录时长。
16. 记录中页面必须展示自动结束倒计时。
17. 达到本次记录时长后，系统自动结束记录。
18. 自动结束不能导致已采集日志丢失。
19. 自动结束原因必须区分：
   - 到达系统默认时长自动结束
   - 到达本次指定时长自动结束

#### 验收标准

1. 不点击结束时，默认 20 分钟后自动结束。
2. 修改配置为 5 分钟后，新记录按 5 分钟自动结束。
3. 选择 10 分钟后，记录在 10 分钟后自动结束。
4. 选择自定义 30 分钟后，记录在 30 分钟后自动结束。
5. 选择固定时长后，用户仍可手动结束记录。
6. 运行中记录不展示修改时长入口。
7. 自动结束后的记录可以正常查看。

### FR-05 长期保存与管理

日志记录必须长期保存，并支持命名、改名和删除。

#### 需求

1. 日志记录默认长期保存。
2. 系统设置中可以配置是否启用自动清理。
3. 默认不自动清理。
4. 历史列表支持：
   - 查看详情
   - 修改名称
   - 修改备注
   - 删除
5. 删除必须二次确认。
6. 删除只删除 K8s Inspector 内部保存的日志记录，不影响 Kubernetes 集群。
7. 删除后不可恢复。

#### 验收标准

1. 已结束记录刷新页面后仍存在。
2. 用户可以修改记录名称。
3. 删除记录前必须二次确认。
4. 删除后历史列表不再展示该记录。

### FR-06 日志查看方式

日志查看必须符合“先选名称空间，再选 Pod”的使用习惯。

#### 需求

1. 打开“复现日志”页面后，用户可以先按名称空间筛选日志记录。
2. 打开某条日志记录后，页面展示该名称空间下有日志的 Pod 列表。
3. 用户点击 Pod 后查看该 Pod 的日志。
4. Pod 列表至少展示：
   - Pod 名称
   - 容器数
   - 日志行数
   - 去重后日志行数
   - 关键字命中数
   - 是否已删除
5. Pod 下支持切换容器。
6. 默认优先展示有关键字命中的 Pod。
7. 无日志的 Pod 默认不展示在详情主列表中，但统计中应显示数量。

#### 验收标准

1. 用户可以按名称空间找到历史日志记录。
2. 打开记录后可以选择具体 Pod。
3. 切换 Pod 后日志内容随之变化。
4. 切换容器后只展示该容器日志。

### FR-07 关键字搜索与高亮

日志内容必须支持搜索和高亮。

#### 需求

1. 日志查看区域提供搜索框。
2. 输入关键字后，高亮当前 Pod 日志中的命中内容。
3. 支持上一个、下一个命中跳转。
4. 支持清空搜索。
5. 默认不区分大小写。
6. 搜索只在当前打开的 Pod 和容器日志中生效。
7. 搜索结果展示命中数量。
8. 日志关键字库命中的内容也要高亮展示。

#### 验收标准

1. 搜索 `error` 后，日志中的 `error` 被高亮。
2. 可以跳转到下一处命中。
3. 清空搜索后，高亮消失。
4. 没有命中时页面提示无匹配结果。

### FR-08 重复日志过滤

系统必须支持过滤重复日志，避免某个 Pod 持续打印相同内容导致结果不可读。

#### 需求

1. 系统保存日志时计算日志指纹。
2. 指纹计算应忽略明显变化但不影响语义的字段，例如：
   - 时间戳
   - trace id
   - request id
   - 数字序号
3. 对同一 Pod、同一容器、同一指纹的连续重复日志进行折叠。
4. 折叠后保留：
   - 第一条出现时间
   - 最后一条出现时间
   - 重复次数
   - 示例日志
5. 页面默认展示折叠后的日志。
6. 用户可以切换查看原始逐行视图。
7. 如果原始逐行视图数据量过大，必须分页或虚拟滚动。

#### 验收标准

1. 同一 Pod 连续打印 1000 行相同日志时，默认展示为 1 条折叠记录和重复次数。
2. 折叠记录能看到首次和末次出现时间。
3. 用户可以切换到原始逐行视图。

### FR-09 脱敏机制

系统必须在保存和展示日志时降低敏感信息泄露风险。

#### 需求

1. 日志入库前先执行脱敏。
2. 脱敏通过规则匹配实现，默认规则包括：
   - `Authorization` 请求头
   - `Cookie` 请求头
   - `token`
   - `password`
   - `secret`
   - `access_key`
   - `private_key`
   - 常见 JWT
   - 手机号
   - 身份证号
3. 脱敏方式为保留字段名，隐藏字段值。
4. 示例：
   - `Authorization: Bearer abcdef` 展示为 `Authorization: Bearer ***`
   - `password=abc123` 展示为 `password=***`
5. 脱敏后的内容再进入数据库。
6. 后端应用日志不得打印未脱敏原始日志。
7. 系统设置支持追加自定义脱敏规则。
8. 自定义规则保存失败时，不得提示已生效。
9. 页面必须标记日志已执行脱敏。

#### 验收标准

1. 包含 `Authorization` 的日志保存后看不到原始 token。
2. 包含 `password=abc123` 的日志保存后展示为 `password=***`。
3. 导出或模板匹配使用的也是脱敏后的日志。

### FR-10 日志模板匹配

系统必须支持对某条日志记录执行模板匹配。

#### 需求

1. 日志记录详情页提供“模板匹配”按钮。
2. 只匹配包含日志条件的模板。
3. 不匹配仅依赖 Pod 状态、事件、资源状态的模板。
4. 匹配范围为当前日志记录中保存的日志。
5. 模板匹配结果展示：
   - 模板名称
   - 严重程度
   - 命中 Pod
   - 命中容器
   - 命中关键字
   - 命中上下文
   - 建议动作
6. 未命中模板不默认展示。
7. 模板匹配不改变问题工作台状态。

#### 验收标准

1. 对日志记录执行模板匹配时，只加载日志类模板。
2. 命中模板后能看到对应 Pod 和上下文。
3. 未命中模板不产生页面噪音。

### FR-11 采集保护

系统必须避免名称空间日志量过大影响生产集群。

#### 需求

1. 系统设置新增复现日志策略。
2. 可配置项包括：
   - 默认记录时长
   - 最大允许记录时长
   - 单名称空间最大 Pod 数
   - 单记录最大日志字节数
   - 单 Pod 最大日志字节数
   - 是否启用重复日志折叠
3. 默认值建议：
   - 默认记录时长：20 分钟
   - 最大允许记录时长：120 分钟
   - 单名称空间最大 Pod 数：200
   - 单记录最大日志字节数：200 MiB
   - 单 Pod 最大日志字节数：20 MiB
   - 启用重复日志折叠：是
4. 超过 Pod 数上限时，不允许开始记录。
5. 达到日志字节上限时，自动停止或停止对应 Pod 采集，并标记截断。
6. 记录详情必须展示是否发生截断。

#### 验收标准

1. 名称空间 Pod 数超过上限时不能开始记录。
2. 达到单记录日志上限时，记录自动停止或标记截断。
3. 截断状态在详情页可见。

### FR-12 API 能力

系统必须提供复现日志记录相关 API。

#### 需求

1. 新增 API：
   - `POST /api/v1/log-recordings/preview`
   - `POST /api/v1/log-recordings`
   - `GET /api/v1/log-recordings`
   - `GET /api/v1/log-recordings/{id}`
   - `PATCH /api/v1/log-recordings/{id}`
   - `POST /api/v1/log-recordings/{id}/stop`
   - `DELETE /api/v1/log-recordings/{id}`
   - `POST /api/v1/log-recordings/{id}/template-match`
   - `GET /api/v1/log-recordings/{id}/pods`
   - `GET /api/v1/log-recordings/{id}/pods/{podName}/containers/{containerName}/logs`
2. 写操作必须校验 CSRF。
3. 所有接口必须受登录保护。
4. 列表接口支持分页和名称空间筛选。
5. 日志查询接口支持分页。
6. 日志查询接口支持返回折叠视图或原始逐行视图。

#### 验收标准

1. 未登录访问接口返回认证错误。
2. 缺少 CSRF 的写操作失败。
3. 历史列表可以按名称空间筛选。
4. Pod 日志接口支持分页返回。

## 8. 数据模型建议

### 8.1 LogRecording

建议字段：

- id
- name
- namespace
- status
- started_at
- ended_at
- planned_end_at
- duration_source
- duration_minutes
- stop_reason
- pod_count
- container_count
- raw_line_count
- folded_line_count
- total_bytes
- truncated
- note

## 9. 页面要求

1. “开始记录”使用主按钮。
2. “结束记录”在记录中状态下明显展示。
3. “删除”使用危险按钮，并必须二次确认。
4. 记录中页面展示：
   - 日志名称
   - 名称空间
   - 触发时间
   - 计划自动结束时间
   - 已记录时长
   - 自动结束倒计时
   - 记录时长来源
   - 已采集 Pod 数
   - 已采集日志行数
5. 日志详情页面布局：
   - 左侧或顶部：Pod 列表
   - 中间：日志内容
   - 顶部工具栏：容器切换、搜索框、折叠视图开关、模板匹配按钮
6. 日志内容使用等宽字体。
7. 长日志必须分页或虚拟滚动，不能一次性渲染大量 DOM。
8. 390px 移动宽度下不能出现内容重叠。
