# K8s Inspector v1.4.0 产品需求文档

## 1. 文档信息

- 产品：K8s Inspector
- 版本：v1.4.0
- 文档状态：草案
- 制定日期：2026-08-13
- 最近更新：2026-08-17
- 前置版本：v1.3.0

## 1.1 需求优先级规则

开发和验收过程中，如果本文档与用户后续口述需求冲突，以用户最新口述需求为准，并同步更新本文档。

## 2. 版本判断

本次功能命名为 v1.4.0，不命名为 v2.0.0。

原因：

1. 本次仍保持单集群、只读、单管理员、SQLite 单副本这些 v1.x 产品边界。
2. v1.3.0 已完成日志巡检、日志记录、模板匹配和日志下载，v1.4.0 不继续扩大日志记录主链路。
3. 本次重点补一个日常有用的小能力：按名称空间查看镜像清单并导出。
4. 本次只保留少量轻量辅助检查，不做完整发布验收平台。
5. 如果后续要做多集群统一纳管、多用户角色、镜像仓库接入、漏洞扫描、Loki/ELK 接入或自动化修复，再考虑 v2.0.0。

## 3. 背景

v1.3.0 已经把日志相关能力做成独立闭环。生产使用中，用户还需要快速知道某些名称空间当前使用了哪些镜像，方便做发布核对、镜像版本排查、外部审计和变更确认。

用户明确调整 v1.4.0 方向：

1. 不再规划“查看服务器上所有镜像列表”，因为 Kubernetes API 只能可靠看到 Pod 引用的镜像，不能直接看到每个节点缓存的全部镜像。
2. 镜像清单只按用户选择的名称空间生成。
3. 名称空间支持多选。
4. 镜像必须覆盖初始化容器和运行容器。
5. 已经执行成功的 Pod，只要 Pod 对象仍能通过 Kubernetes API 看到，也要纳入统计。
6. 镜像列表支持导出 `.txt` 文件。

上一版中过重的环境自检和发布验收方向不纳入 v1.4.0。

## 4. 产品目标

1. 支持按一个或多个名称空间查看 Kubernetes API 可见 Pod 引用的镜像清单。
2. 镜像来源覆盖 `initContainers`、`containers`、`initContainerStatuses`、`containerStatuses`。
3. 镜像按镜像地址去重，并保留名称空间、Pod、容器、来源类型等引用信息。
4. 支持导出当前筛选结果为 `.txt` 文件。
5. 对无法获取镜像的情况给出明确原因，例如未选择名称空间、无 Pod、权限不足或 Kubernetes Provider 不可用。
6. 保留轻量部署路径检查和通知测试能力，帮助确认当前部署是否能正常访问和发通知。
7. 保持只读，不申请管理员权限，不执行 Pod exec，不修改集群资源。

## 5. 非目标

v1.4.0 不做以下事项：

1. 不查看节点或服务器本地缓存的全部镜像。
2. 不接入镜像仓库。
3. 不拉取镜像。
4. 不扫描镜像漏洞。
5. 不解析镜像层、SBOM 或签名。
6. 不判断镜像是否可以被集群重新拉取。
7. 不做多集群统一管理。
8. 不做多用户、角色权限或企业 SSO。
9. 不接入 Loki、ELK、OpenSearch 等外部日志平台。
10. 不自动修复 Kubernetes 资源。
11. 不执行 Pod exec。
12. 不创建、更新或删除业务资源。
13. 不做完整发布验收平台。
14. 不持久化自检结果。

## 6. 核心流程

### 6.1 镜像清单查看

1. 用户进入“镜像清单”页面。
2. 用户选择一个或多个名称空间。
3. 系统读取这些名称空间下 Kubernetes API 可见的 Pod。
4. 系统从 Pod 规格和 Pod 状态中提取镜像。
5. 系统按镜像地址去重展示镜像清单。
6. 用户点击某个镜像，可以查看该镜像被哪些名称空间、Pod、容器引用。
7. 用户可以导出当前筛选结果为 `.txt` 文件。

### 6.2 部署路径检查

1. 用户进入“系统设置”。
2. 用户执行轻量部署路径检查。
3. 系统检查前端当前访问路径、后端 API 前缀和健康检查路径是否一致。
4. 如果不一致，展示影响和建议处理方式。

### 6.3 通知测试

1. 用户进入“系统设置”的通知配置区域。
2. 用户点击测试通知。
3. 系统向当前配置的通知渠道发送测试消息。
4. 页面展示发送结果和失败原因。

## 7. 功能需求

### FR-01 镜像清单入口

系统必须提供独立的镜像清单入口。

#### 需求

1. 左侧导航新增“镜像清单”。
2. 镜像清单属于资源查看类功能，不放在日志巡检或日志记录页面内。
3. 页面顶部提供名称空间多选筛选框。
4. 未选择名称空间时，不自动查询镜像。
5. 未选择名称空间时，页面提示“请选择名称空间后查看镜像清单”。
6. 不提供“全部名称空间”一键选择。

#### 验收标准

1. 用户可以从左侧导航进入镜像清单。
2. 未选择名称空间时不会触发全量集群查询。
3. 用户可以选择多个名称空间并触发查询。

### FR-02 镜像采集范围

系统必须从 Kubernetes API 可见 Pod 中提取镜像。

#### 需求

1. 每个选中名称空间内，系统读取该名称空间下所有可见 Pod。
2. 镜像来源包括：
   - `pod.spec.initContainers[].image`
   - `pod.spec.containers[].image`
   - `pod.status.initContainerStatuses[].image`
   - `pod.status.initContainerStatuses[].imageID`
   - `pod.status.containerStatuses[].image`
   - `pod.status.containerStatuses[].imageID`
3. 已完成或成功退出的 Pod，如果 Pod 对象仍然存在，必须纳入统计。
4. 已被删除且 Kubernetes API 已不可见的 Pod，不纳入统计。
5. Mock Provider 必须能返回稳定的模拟镜像数据，便于本地开发和测试。

#### 验收标准

1. 初始化容器镜像会出现在镜像清单中。
2. 运行容器镜像会出现在镜像清单中。
3. Pod 状态中的 `imageID` 可见时会作为详情信息展示。
4. 已完成但仍可见的 Pod 会被统计。
5. 无 Pod 的名称空间展示为空状态，不报错。

### FR-03 镜像去重与展示

系统必须对镜像做去重展示，并保留引用详情。

#### 需求

1. 主列表按规范化后的镜像地址去重。
2. 镜像规范化只做安全、可解释的处理：
   - 去掉首尾空格
   - 保持 registry、repository、tag、digest 原样
   - 不猜测默认 registry
   - 不把 tag 和 digest 合并改写
3. 主列表展示：
   - 镜像
   - 引用名称空间数
   - 引用 Pod 数
   - 引用容器数
   - 最近 Pod 创建时间
   - 最近 Pod 状态
4. 详情展示：
   - 名称空间
   - Pod
   - Pod 阶段
   - 容器
   - 容器类型：初始化容器 / 运行容器
   - 镜像来源：spec / status / imageID
   - Pod 创建时间
5. 长镜像地址必须支持完整查看和复制。
6. 页面表格要支持搜索镜像关键字。

#### 验收标准

1. 同一个镜像被多个 Pod 使用时，主列表只显示一行。
2. 点击详情能看到全部引用位置。
3. 长镜像地址不会撑坏页面。
4. 用户可以复制完整镜像地址。

### FR-04 镜像导出

系统必须支持导出当前筛选结果为 `.txt` 文件。

#### 需求

1. 导出内容必须基于当前选择的名称空间和当前搜索条件。
2. 导出文件后缀为 `.txt`。
3. 文件名格式建议为 `k8s-inspector-images-YYYYMMDD-HHmmss.txt`。
4. 文本内容至少包含：
   - 导出时间
   - 名称空间范围
   - 镜像总数
   - 每个镜像地址
   - 每个镜像的引用详情
5. 导出接口必须校验 CSRF 或使用现有下载安全机制。
6. 导出失败时页面展示明确错误。

#### 验收标准

1. 用户可以下载 `.txt` 镜像清单。
2. 下载文件能直接被文本编辑器打开。
3. 导出内容与页面当前筛选结果一致。
4. 未选择名称空间时不能导出，并提示原因。

### FR-05 部署路径检查

系统保留轻量部署路径检查，帮助定位根路径、子路径或双入口部署问题。

#### 需求

1. 检查当前前端访问路径。
2. 检查后端 API 前缀是否可访问。
3. 检查健康检查接口是否可访问。
4. 检查静态资源路径是否异常。
5. 不生成持久化检查记录。
6. 不要求用户执行完整发布验收。

#### 验收标准

1. 根路径部署下检查结果正常。
2. 子路径部署下能识别当前路径前缀。
3. API 前缀错误时展示明确失败原因。

### FR-06 通知测试

系统保留通知测试能力，帮助确认 Webhook 配置是否有效。

#### 需求

1. 用户可以对已配置通知渠道发送测试消息。
2. 测试消息必须明确标记为测试消息。
3. 发送失败时展示 HTTP 状态码或后端错误摘要。
4. 不把测试通知写成发布验收记录。

#### 验收标准

1. 通知配置正确时能收到测试消息。
2. Webhook 地址无效时页面展示失败原因。
3. 未配置通知渠道时提示先配置。

### FR-07 API 能力

系统必须提供镜像清单查询和导出接口。

#### 需求

1. 新增镜像清单查询接口。
2. 新增镜像清单导出接口。
3. 查询接口必须要求至少一个名称空间。
4. 查询接口支持多个名称空间。
5. 查询接口支持镜像关键字搜索。
6. 查询接口支持分页或合理的返回上限。
7. 导出接口复用相同筛选条件。

#### 建议接口

1. `GET /api/v1/images`
2. `GET /api/v1/images/export`

#### 验收标准

1. 不传名称空间时返回 422。
2. 传多个名称空间时返回合并去重后的结果。
3. Kubernetes 权限不足时返回可读错误。
4. 导出接口返回 `text/plain` 或文件下载响应。

## 8. 数据结构

v1.4.0 不新增持久化表。

### 8.1 ImageInventoryItem

镜像主列表响应建议字段：

- `image`
- `namespace_count`
- `pod_count`
- `container_count`
- `latest_pod_created_at`
- `latest_pod_phase`
- `references`

### 8.2 ImageInventoryReference

镜像引用详情建议字段：

- `namespace`
- `pod_name`
- `pod_phase`
- `container_name`
- `container_type`
- `source`
- `image`
- `image_id`
- `pod_created_at`

### 9.1 左侧导航

建议导航调整为：

1. 问题工作台

3. 日志巡检

### 9.2 镜像清单页面

   - 查询按钮

4. 镜像表格
5. 镜像详情弹窗或侧边抽屉

## 10. 权限与安全

1. 镜像清单只需要读取 Pod。
2. 不需要读取 Secret。
3. 不需要读取节点本地镜像缓存。
4. 不需要访问镜像仓库。
5. 不需要 Pod exec 权限。
6. 不需要创建、更新或删除 Kubernetes 资源。
7. 导出接口必须沿用现有认证和 CSRF 策略。
8. 镜像地址不做脱敏，除非后续确认镜像地址中存在敏感信息。

## 11. 错误处理

### 11.1 未选择名称空间

提示：请选择名称空间后查看镜像清单。

### 11.2 Kubernetes Provider 不可用

提示：当前未连接真实 Kubernetes 集群，无法读取真实镜像清单。

Mock Provider 下应明确标记为模拟数据。

### 11.3 权限不足

提示：当前账号缺少读取 Pod 的权限，无法生成镜像清单。

### 11.4 无 Pod

提示：所选名称空间下没有可见 Pod。

### 11.5 导出失败

提示：镜像清单导出失败，请稍后重试或查看后端日志。

## 12. 验收标准

v1.4.0 发布前必须满足：

1. 可以选择单个名称空间查看镜像清单。
2. 可以选择多个名称空间查看合并去重后的镜像清单。
3. 初始化容器镜像被统计。
4. 运行容器镜像被统计。
5. 已完成但仍可见的 Pod 被统计。
6. 长镜像地址可完整查看和复制。
7. 当前筛选结果可以导出 `.txt` 文件。
8. 未选择名称空间时不会查询全集群。
9. Mock Provider 有稳定测试数据。
10. Kubernetes Provider 权限不足时有明确错误。
11. 部署路径检查不影响已有功能。
12. 通知测试不影响已有通知配置。
13. README 和 v1.4.0 文档说明镜像清单能力边界。

## 13. 测试要求

### 13.1 后端测试

1. 镜像提取覆盖 `initContainers`。
2. 镜像提取覆盖 `containers`。
3. 镜像提取覆盖 `containerStatuses.image`。
4. 镜像提取覆盖 `containerStatuses.imageID`。
5. 多名称空间结果去重正确。
6. 未选择名称空间返回 422。
7. 导出 `.txt` 内容与查询结果一致。

### 13.2 前端测试

1. 名称空间多选可用。
2. 未选择名称空间时展示空状态。
3. 查询后表格展示镜像清单。
4. 长镜像地址不破坏布局。
5. 详情弹窗或抽屉展示引用详情。
6. 导出按钮可下载文件。

### 13.3 人工验收

1. 在 Mock Provider 下验证页面流程。
2. 在真实 Kubernetes Provider 下选择一个有 Pod 的名称空间验证镜像清单。
3. 对一个包含初始化容器的 Pod 验证镜像是否出现。
4. 对一个已完成但仍可见的 Pod 验证镜像是否出现。
5. 下载 `.txt` 文件并核对内容。

## 14. 风险与边界

1. Kubernetes API 看不到节点上已经缓存但没有被 Pod 引用的镜像。
2. Kubernetes API 看不到已经被删除的 Pod 引用过的镜像。
3. 部分运行时可能不返回完整 `imageID`。
4. 镜像地址可能非常长，前端必须处理换行、截断和复制。
5. 大名称空间下 Pod 数较多，需要分页、上限或加载状态。
6. 权限不足时只能提示用户补充只读 Pod 权限，系统不自动申请权限。

## 15. 开发切片建议

### Step 1：后端镜像提取能力

1. 在 Kubernetes Provider 中补充按名称空间列出 Pod 镜像的方法。
2. 实现镜像规范化、去重和引用详情构建。
3. 补充 Mock Provider 镜像数据。
4. 补充单元测试。

### Step 2：镜像查询与导出 API

1. 新增镜像清单查询接口。
2. 新增 `.txt` 导出接口。
3. 处理未选择名称空间、权限不足、Provider 不可用等错误。
4. 补充 API 测试。

### Step 3：前端镜像清单页面

1. 新增左侧导航入口。
2. 实现名称空间多选。
3. 实现镜像表格、搜索、详情和复制。
4. 实现导出按钮。
5. 做桌面宽度和长镜像地址布局验证。

### Step 4：轻量部署路径与通知测试收尾

1. 保留或补齐部署路径检查。
2. 保留或补齐通知测试。
3. 不做持久化验收记录。

### Step 5：文档与发布验收

1. 更新 README。
2. 新增或更新 v1.4.0 验收报告。
3. 明确说明镜像清单只来自 Kubernetes API 可见 Pod，不代表节点全部缓存镜像。
