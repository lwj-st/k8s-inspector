# K8s Inspector v1.2.0 产品需求文档

## 1. 文档信息

- 产品：K8s Inspector
- 版本：v1.2.0
- 文档状态：草案
- 制定日期：2026-08-03
- 前置版本：v1.1.0

## 1.1 需求优先级规则

开发和验收过程中，如果本文档与用户后续口述需求冲突，以用户最新口述需求为准，并同步更新本文档。

## 2. 背景

v1.1.0 已完成状态巡检、日志巡检、模板检查、问题工作台、问题详情、忽略、通知、定时巡检、系统设置、必需组件和管理员改密等能力。

当前主要问题不是“缺少更多检查项”，而是页面信息过多、主次不清，用户进入页面后不容易判断：

1. 当前最需要处理的问题是什么。
2. 证据里哪些信息能直接定位故障。
3. 哪些内容只是技术字段或辅助信息。
4. 模板检查未命中时是否需要关注。
5. 根路径和子路径部署是否都能稳定访问。

v1.2.0 重点解决信息架构、页面降噪、访问兼容和可验证交付问题，不引入高风险自动修复能力。

## 3. 产品目标

1. 页面默认只展示用户排障需要优先关注的信息。
2. 描述性、宣传性、解释性文案默认不展示；只有影响用户操作理解、风险判断或下一步动作的提示才保留。
3. 状态巡检、日志巡检、模板检查各自只展示本功能相关结果，不混用其它巡检模块的信息。
4. 模板检查未命中时不展示未命中模板列表；全部未命中时也不展示额外空提示。
5. 问题详情优先展示结论、影响对象、证据和可执行检查命令。
6. 同一版本必须支持根路径访问和子路径访问两种部署方式。
7. 所有改动不得破坏 v1.0.0 和 v1.1.0 已交付功能。

## 4. 非目标

v1.2.0 不做以下事项：

1. 不做自动修复 Kubernetes 资源。
2. 不做飞书应用机器人，只保留已有通知类能力。
3. 不做多集群统一纳管。
4. 不做复杂权限体系，仍保持单管理员模型。
5. 不做升级/回退演练功能。
6. 不新增营销式页面文案，例如“可信巡检与主动发现”“管理区”等不影响操作的描述。
7. 不把未命中的模板、正常对象明细、大量技术字段作为默认展示内容。

## 5. 用户角色与使用原则

### 5.1 用户角色

- 实施运维
- 平台运维

### 5.2 使用原则

1. 默认视图回答“哪里坏了、为什么、怎么查”。
2. 正常内容默认收起，异常内容默认展开。
3. 技术字段默认收起，但需要能查看。
4. 表格列不堆满页面；关键结论允许换行，其它列可截断并通过悬浮查看完整内容。
5. 操作按钮只保留真实可执行动作，不提供多余按钮。
6. 文案必须短、明确、能指导操作。

## 6. 版本范围

### FR-01 页面文案降噪

系统必须清理不影响用户操作的描述性文字。

#### 需求

1. 页面眉标、说明、副标题中不再展示无操作价值的口号式文案。
2. 以下文案不应继续作为默认页面信息展示：
   - “可信巡检与主动发现”
   - “管理区”
   - “计划、通知和巡检策略不会占用日常排障工作台”
   - “汇总手动巡检和定时巡检发现的当前问题；同一问题会自动去重和更新状态”
3. 可以保留影响使用的提示，例如：
   - 登录失败原因
   - 巡检失败原因
   - RBAC 权限不足
   - 日志读取保护
   - 配置保存失败
   - 删除、忽略、恢复忽略等二次确认
4. 所有保留提示必须说明用户下一步能做什么。

#### 验收标准

1. 全局搜索上述无操作价值文案，前端默认页面不再出现。
2. 删除文案后页面功能入口仍清晰可识别。
3. 错误、风险和二次确认提示不被误删。

### FR-02 问题工作台信息层级优化

问题工作台必须优先展示当前开放问题，减少干扰信息。

#### 需求

1. 默认列表只展示开放问题，不展示已恢复和已忽略问题。
2. 已忽略问题只能通过筛选项查看。
3. 已恢复问题只能通过筛选项查看。
4. 表格列优先级：
   - 严重程度
   - 结论
   - 资源
   - 名称空间
   - 巡检项
   - 状态
   - 持续时间
   - 最后发现
   - 确认
   - 操作
5. 结论列允许换行。
6. 除结论外，其它列固定宽度；显示不全时省略，鼠标悬浮显示完整值。
7. 文本可通过用户手动选中复制，不提供每个单元格一个复制按钮。
8. 状态、确认状态使用清晰颜色区分：
   - 开放：黄色
   - 已恢复：绿色
   - 已忽略：灰色
   - 未确认：黄色
   - 已确认：绿色
9. “刷新”按钮使用明确主按钮样式，点击后刷新当前筛选结果。
10. 支持用户自定义问题列表列显示。
11. 支持用户调整问题列表列宽。
12. 列显示和列宽配置必须持久化，刷新页面后保持。
13. 必须提供“恢复默认列设置”入口。

#### 验收标准

1. 1366px 宽度下表格不出现明显挤压换行。
2. 结论以外的列不会因为换行导致行高异常。
3. 已忽略问题默认不出现在开放列表。
4. 修复后的问题在一次成功覆盖巡检后能从开放列表移出。
5. 用户隐藏“确认”列后刷新页面，列仍保持隐藏。
6. 用户调整“结论”列宽后刷新页面，列宽仍保持。
7. 点击“恢复默认列设置”后，列显示和列宽恢复系统默认值。

### FR-03 问题详情聚焦定位

问题详情页必须让用户先看到能定位问题的信息。

#### 需求

1. 顶部展示问题结论、严重程度、状态和资源路径。
2. “结论与影响范围”默认只展示：
   - 判断原因
   - 资源
   - 最后发现
   - 出现次数
   - 确认状态
   - 建议动作
3. 集群、范围、首次发现、内部编码等技术字段默认折叠。
4. 证据区展示证据数量。
5. 查看命令区只提供能定位当前问题的命令。
6. 命令必须可直接复制执行，不允许出现需要用户手动替换的 Pod 名、Namespace 或资源名。
7. 如果某类问题无法生成确定命令，则不展示命令区，避免误导。
8. 忽略问题必须二次确认。
9. 已忽略问题详情必须提供“恢复显示”能力。

#### 验收标准

1. 打开详情页后首屏能看到结论和下一步动作。
2. 命令数量控制在定位问题所需范围内，不输出泛化命令集合。
3. 已忽略问题可恢复到开放列表。
4. 已忽略问题修复后不再作为开放或已忽略问题继续展示。

### FR-04 状态巡检页面优化

状态巡检只展示状态巡检结果，不混入日志巡检或模板检查的展示逻辑。

#### 需求

1. 巡检完成后优先展示异常资源。
2. 正常资源默认折叠。
3. 覆盖信息默认折叠在底部。
4. 覆盖摘要必须说明：
   - 本次检查了哪些巡检项
   - 哪些成功
   - 哪些跳过
   - 哪些失败
5. 多范围巡检摘要必须显示总异常数，不使用“发现 2 个异常；发现 6 个异常”这类无法理解的拼接文案。
6. “38 个范围”这类描述必须明确其含义，例如“38 个名称空间”或“38 个检查范围”。
7. 首页或问题工作台数据刷新必须与状态巡检结果同步；成功完成巡检后，开放问题列表能刷新到最新状态。

#### 验收标准

1. 状态巡检成功后能触发问题工作台刷新。
2. 修复并删除资源后，重新运行覆盖该资源范围的状态巡检，旧问题应恢复或不再显示为开放。
3. 覆盖摘要默认不占据主要排障区域。

### FR-05 日志巡检页面优化

日志巡检只展示日志相关结果。

#### 需求

1. 日志巡检页面不展示“本次巡检结论”和“本次巡检覆盖”这类状态巡检模块信息。
2. 未命中关键字时，结论显示正常。
3. 命中关键字时，必须展示：
   - Pod
   - 容器
   - 关键字
   - 命中时间或日志行时间
   - 命中上下文
4. 命中上下文必须明确说明不是完整日志。
5. 如果原始日志被截断，页面必须标明已截断。
6. 日志读取保护只在无法确认 Pod 数量或超过安全阈值时出现。
7. 如果第一次点击日志巡检时发现数据缺失，系统应自动刷新必要发现数据后继续巡检；不能要求用户点第二次。

#### 验收标准

1. 无关键字命中时显示正常，不显示未知。
2. 命中 `error` 时，原始日志或上下文中必须能看到命中的实际文本。
3. 大范围日志巡检保护有明确原因和缩小范围入口。
4. 单 Pod 日志巡检不被大范围保护误拦截。

### FR-06 模板检查页面优化

模板检查只展示命中和无法判断的模板。

#### 需求

1. 未命中的模板不展示。
2. 未命中模板数量不展示。
3. 全部未命中时，不展示额外空提示，避免制造需要处理的噪音。
4. 命中模板展示：
   - 模板名称
   - 严重程度
   - 命中条件
   - 命中证据
   - 建议动作
5. 无法判断模板展示：
   - 模板名称
   - 无法判断原因
   - 建议动作
6. 模板检查不得展示状态巡检覆盖摘要。

#### 验收标准

1. 页面全局搜索不到“未命中模板”默认展示文案。
2. 模板未命中不会制造用户需要处理的噪音。
3. 全部未命中时不展示“本次没有命中故障模板”等空提示。
4. 命中和无法判断结果仍可正常查看证据。

### FR-07 名称空间证据抽屉优化

名称空间证据抽屉必须优先展示摘要和异常。

#### 需求

1. 顶部重点摘要展示：
   - Pod 总数
   - 异常 Pod 数
   - CPU
   - 内存
2. 无异常分类时不展示“无异常分类”。
3. 详细字段默认折叠。
4. 正常 Pod、正常 Service、正常 Ingress、正常 TLS Secret 默认折叠。
5. 异常 Pod 和异常对象默认展开。
6. 资源使用没有采集到时，只在相关位置提示“未采集到 Metrics 样本”，不重复提示。

#### 验收标准

1. 打开抽屉首屏能看到是否异常和异常数量。
2. 无异常时页面高度明显减少。
3. 正常明细仍可手动展开查看。

### FR-08 系统设置收敛

系统设置页面只保留配置动作和必要解释。

#### 需求

1. 移除“管理区”等无操作价值文案。
2. 每个设置项只保留必要说明：
   - 该配置影响什么
   - 不配置会怎样
   - 保存失败如何处理
3. 必需组件手动添加必须通过下拉选择已有资源，不允许纯手填关键字段。
4. 集群标识必须可在系统设置中修改，不依赖环境变量作为唯一来源。
5. 更改密码入口放在左下用户区域，流程保持：
   - 输入旧密码
   - 输入新密码
   - 确认新密码
   - 保存后提示重新登录或继续使用当前会话

#### 验收标准

1. 设置页面无口号式文案。
2. 配置项说明不会遮挡主要操作。
3. 必需组件可通过下拉选择添加。
4. 集群标识保存后新巡检结果使用新标识。

### FR-09 主题系统与基础视觉规范

系统必须支持亮色和暗色两套主题。默认使用亮色主题，整体降低视觉噪音，按钮、字体和间距参考用户提供的示例图。

#### 需求

1. 系统提供主题切换能力：
   - 支持亮色主题
   - 支持暗色主题
   - 默认亮色主题
   - 主题切换入口放在左下用户菜单或系统设置中，优先放在左下用户菜单
   - 用户切换后必须持久化，下次打开系统仍使用上次选择
2. 亮色主题以白色和浅灰为主：
   - 页面背景：浅灰白
   - 内容卡片：白色
   - 边框：浅灰
   - 主色：蓝色，用于主按钮、当前选中和关键操作
   - 告警色：黄色，仅用于告警、待处理、未确认等状态
   - 危险色：红色，仅用于删除、危险确认、严重故障等状态
3. 暗色主题以深灰和黑灰为主：
   - 页面背景：深灰或近黑
   - 内容卡片：深灰
   - 边框：中性深灰
   - 正文、标题、表格文字必须保证可读性
   - 主色仍使用蓝色
   - 告警色仍使用黄色
   - 危险色仍使用红色
4. 暗色主题不是简单反色，必须保证：
   - 表格边框可辨认
   - 输入框可辨认
   - 弹窗可辨认
   - 状态徽标可辨认
   - 日志和命令块可读
5. 亮色主题下不再使用大面积深色侧边栏；暗色主题下允许深色侧边栏，但不能和内容区层级混乱。
6. 左侧导航主功能字体参考示例：
   - 字号适中
   - 字重清晰
   - 当前选中项使用高亮底色、左侧高亮线或清晰文字色
   - 未选中项保持低干扰
7. 系统内部字体参考示例：
   - 系统整体字体不要过大
   - 标题清晰但克制，不使用超大字号
   - 正文字体偏常规，不使用过重字重
   - 表格和卡片正文保持紧凑，避免一屏只能看到少量信息
   - 表格、卡片、说明文字层级明确
8. 内容卡片参考示例：
   - 亮色主题白底，暗色主题深灰底
   - 圆角
   - 轻边框
   - 弱阴影或无阴影
   - 页面留白充足
9. 顶部页签或二级导航参考示例：
   - 当前项使用下划线、高亮文字或轻量背景
   - 不使用过多颜色块
10. 按钮样式参考用户提供示例：
   - 主按钮为蓝色实底，例如“创建”“保存”“巡检”
   - 次按钮为背景色底加浅边框，例如“刷新”“取消”“返回”
   - 分段切换按钮使用轻量容器，当前项蓝色文字或浅蓝底
   - 告警动作使用黄色，不用于普通主按钮
   - 危险动作使用红色，例如删除、清空、不可逆确认
   - 按钮图标和文字必须垂直居中对齐
   - 图标与文字间距一致，不出现图标偏上、文字偏下
   - 按钮高度、圆角、内边距在全系统保持一致
11. 左下角用户区域改为可点击用户卡片：
   - 显示头像或首字母
   - 显示用户名
   - 点击后弹出菜单
12. 用户菜单参考示例，至少包含：
   - 主题切换
   - 更改密码
   - 注销
13. 主题切换可使用“亮色/暗色”分段按钮或菜单项，文案必须明确。
14. 如果后续存在管理类入口，可放入用户菜单或设置页，不在日常主导航里制造噪音。
15. 用户菜单必须点击外部可关闭，按 `Esc` 可关闭。
16. 用户菜单按钮和菜单项必须支持键盘访问。
17. 移动端或窄屏下，侧边栏和用户菜单不得遮挡主要内容。

#### 验收标准

1. 默认打开系统是亮色主题。
2. 用户可以切换到暗色主题。
3. 切换主题后刷新页面，主题保持不变。
4. 亮色主题不出现大面积深色背景。
5. 暗色主题下主要页面、表格、弹窗、输入框、命令块、日志块均可读。
6. 左侧主导航字体和间距清晰，当前页面状态明确。
7. 内容区标题、正文、表格文字层级统一。
8. 系统整体字体不过大，列表页一屏能看到足够排障信息。
9. 主按钮使用蓝色，普通操作不再使用绿色作为主色。
10. 黄色只用于告警状态或告警动作。
11. 红色只用于危险状态或危险操作。
12. 带图标按钮中文字和图标垂直居中对齐。
13. 左下用户卡片点击后出现菜单。
14. 菜单中的“主题切换”“更改密码”和“注销”可正常操作。
15. 用户菜单支持点击外部关闭和 `Esc` 关闭。
16. 1366px 桌面宽度下无横向滚动。
17. 390px 移动宽度下无内容溢出。

### FR-10 访问路径兼容

系统必须支持两种访问形式：

1. 根路径访问：`https://xxx/`
2. 子路径访问：`https://xxx/inspector/`

#### 需求

1. 同一版本镜像和 Helm Chart 必须支持根路径部署和子路径部署。
2. 前端路由、静态资源、API 请求、登录跳转、退出登录、问题详情链接、通知中的详情页链接都必须正确处理 base path。
3. 根路径部署时：
   - 页面入口为 `/`
   - API 不带 `/inspector` 前缀
   - 刷新任意前端路由不 404
4. 子路径部署时：
   - 页面入口为 `/inspector/`
   - 前端路由在 `/inspector/*` 下工作
   - API 路径按部署配置正确转发
   - 刷新 `/inspector/issues/:id` 等前端路由不 404
5. Helm values 必须提供明确配置项控制访问路径。
6. README 和升级文档必须分别给出根路径和子路径部署示例。

#### 验收标准

1. 根路径模式 E2E 通过。
2. 子路径模式 E2E 通过。
3. 两种模式下登录、刷新、问题详情、系统设置、通知详情链接都可用。
4. README 中命令可以直接复制执行。

### FR-11 问题批量处理

问题工作台必须支持对多个问题进行批量操作，减少重复处理成本。

#### 需求

1. 问题列表支持多选。
2. 批量操作只对当前筛选结果中被选中的问题生效。
3. 支持批量确认问题。
4. 支持批量忽略问题。
5. 支持批量恢复显示已忽略问题。
6. 批量忽略和批量恢复显示必须二次确认。
7. 批量确认必须允许填写统一备注。
8. 批量操作完成后，列表和统计数据必须刷新。
9. 批量操作失败时必须展示失败原因；部分成功时必须说明成功和失败数量。
10. 不允许批量删除问题；问题生命周期仍由巡检结果驱动。

#### 验收标准

1. 选择 3 个开放问题后，可以一次性确认。
2. 选择 3 个开放问题后，可以一次性忽略，忽略后默认开放列表不再显示。
3. 在已忽略筛选中选择问题，可以批量恢复显示。
4. 批量操作出现部分失败时，页面展示成功数和失败数。
5. 批量操作不会修改问题的真实健康状态。

### FR-12 问题处理记录

问题详情必须支持记录人工处理过程，方便交接和复盘。

#### 需求

1. 问题详情支持添加处理记录。
2. 处理记录至少包含：
   - 记录内容
   - 创建时间
   - 创建人
3. 处理记录按时间倒序展示。
4. 处理记录内容必须支持普通文本，不要求富文本。
5. 处理记录不得影响问题 open/recovered/ignored 状态。
6. 确认问题、忽略问题、恢复显示等操作也应进入生命周期记录。
7. 处理记录不得泄露敏感配置；前端和后端都要复用现有敏感信息脱敏策略。

#### 验收标准

1. 用户能在问题详情添加一条处理记录。
2. 刷新页面后处理记录仍存在。
3. 多条处理记录按时间倒序展示。
4. 处理记录不改变问题健康状态。

### FR-13 证据筛选与结果导出

系统必须支持在问题详情中快速筛选证据，并导出排障信息。

#### 需求

1. 问题详情证据区支持按证据类型筛选。
2. 证据类型至少包括：
   - Kubernetes API
   - Event
   - Log
   - Metrics
   - Config
   - Command
3. 默认展示全部关键证据；正常或低价值证据保持折叠。
4. 支持导出单个问题为 Markdown。
5. 导出内容必须包含：
   - 问题结论
   - 资源
   - 名称空间
   - 严重程度
   - 当前状态
   - 判断原因
   - 建议动作
   - 关键证据
   - 查看命令
   - 处理记录
6. 导出内容必须脱敏。
7. 支持复制 Markdown 到剪贴板。
8. 支持下载 `.md` 文件。
9. 如果浏览器不支持剪贴板 API，仍可下载文件。

#### 验收标准

1. 问题详情中可以按 Log 证据筛选。
2. 问题详情中可以按 Kubernetes API 证据筛选。
3. 导出的 Markdown 不包含密码、token、完整 Webhook Secret、Cookie、Authorization。
4. 复制失败时给出可理解提示，不影响下载。

### FR-14 自动刷新与维护静默

系统必须减少人工刷新次数，并支持维护窗口内降低告警干扰。

#### 需求

1. 问题工作台支持自动刷新开关。
2. 自动刷新间隔可配置，默认 30 秒。
3. 自动刷新时不得打断用户正在输入的内容。
4. 如果用户正在查看详情或填写备注，自动刷新不能关闭弹窗或清空表单。
5. 状态巡检完成后，问题工作台应立即刷新问题列表和统计。
6. 系统支持维护静默窗口。
7. 维护静默窗口至少包含：
   - 名称
   - 开始时间
   - 结束时间
   - 影响范围：全集群、名称空间、资源类型或 Label Selector
   - 备注
   - 启用状态
8. 静默窗口内新问题仍然记录到问题工作台。
9. 静默窗口内通知应被抑制，并在问题生命周期中记录“通知已静默”。
10. 严重程度升级是否突破静默必须可配置，默认不突破。
11. 静默结束后，如果问题仍然开放，不补发静默期间每一条通知，只发送一次当前仍开放摘要。

#### 验收标准

1. 开启自动刷新后，问题列表按配置间隔刷新。
2. 用户正在填写确认备注时，自动刷新不清空输入框。
3. 创建维护静默后，匹配范围内的问题不发送通知。
4. 静默窗口内的问题仍能在问题工作台看到。
5. 静默结束后仍开放的问题只发送一次摘要通知。

### FR-15 双入口访问增强

系统必须支持同一版本按配置部署为根路径或子路径；v1.2.0 同时纳入同实例双入口增强。

#### 需求

1. 继续支持部署时选择根路径访问：`https://xxx/`。
2. 继续支持部署时选择子路径访问：`https://xxx/inspector/`。
3. 新增支持同一个实例同时通过以下两个入口访问：
   - `https://xxx/`
   - `https://xxx/inspector/`
4. 同实例双入口启用方式必须通过 Helm values 明确配置，默认关闭。
5. 双入口模式下，前端静态资源、API 请求、登录、退出、详情页刷新都必须可用。
6. 双入口模式下通知详情链接使用系统设置中的外部访问地址生成。
7. 如果网关需要 rewrite 或 strip path，README 必须给出明确示例。

#### 验收标准

1. 单根路径模式可用。
2. 单 `/inspector/` 子路径模式可用。
3. 双入口模式下 `/` 可登录、刷新和打开问题详情。
4. 双入口模式下 `/inspector/` 可登录、刷新和打开问题详情。
5. README 中说明三种部署方式：根路径、子路径、双入口。

### FR-16 商用交付质量

v1.2.0 必须保持可交付质量。

#### 需求

1. 不删除 v1.0.0 和 v1.1.0 已有 API 字段。
2. 不改变已有问题编码语义。
3. 不降低 Kubernetes 只读权限边界。
4. 不把 Secret、Webhook 完整地址、密码哈希、加密密钥输出到页面或日志。
5. 所有新增 UI 状态必须有测试覆盖。
6. 所有路径兼容逻辑必须有测试覆盖。
7. README 必须与 Helm values 保持一致。

#### 验收标准

1. 后端测试通过。
2. 前端测试通过。
3. 前端构建通过。
4. Helm template 渲染通过。
5. 根路径和子路径访问测试通过。
6. 从 v1.1.0 升级后数据保留。

## 7. 优先级

### P0

1. 页面文案降噪。
2. 问题工作台信息层级优化。
3. 问题详情聚焦定位。
4. 状态巡检、日志巡检、模板检查页面边界修正。
5. 模板未命中不展示。
6. 名称空间证据抽屉优化。
7. 亮色/暗色主题与基础视觉规范。
8. 问题批量确认、批量忽略和批量恢复显示。
9. 问题处理记录。
10. 问题详情证据筛选。
11. 单问题 Markdown 导出和复制。
12. 自动刷新。
13. 维护静默窗口。
14. 根路径、子路径和同实例双入口访问兼容。
15. 测试和文档补齐。

### P1

1. 问题列表列配置交互优化，例如拖拽排序。
2. 多问题批量导出 Markdown。
3. 静默窗口日历视图。
4. 问题处理记录支持附件。

### 暂不做

1. 自动修复。
2. 多集群。
3. 复杂 RBAC。
4. 插件市场。
5. AI 自动根因归并。

## 8. 页面文案规则

### 8.1 必须删除的文案类型

1. 口号式文案。
2. 解释产品定位但不影响操作的文案。
3. 页面区域自夸式描述。
4. 用户已经能从标题理解的重复说明。
5. 正常状态下反复出现的“没有异常”“没有命中”列表。

### 8.2 必须保留的文案类型

1. 错误原因。
2. 权限不足原因。
3. 需要用户选择或确认的风险说明。
4. 会影响巡检结果可信度的提示。
5. 会影响部署、登录、通知、路径访问的配置说明。

### 8.3 文案验收方式

1. 使用全局搜索检查无效文案是否残留。
2. 使用真实页面检查删除文案后是否仍能完成任务。
3. 每条保留说明必须能回答“用户下一步该做什么”。
